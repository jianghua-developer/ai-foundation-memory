## 关键架构要点（开发时不得违背）

- **SDD 规范生产段**：只做 fact → spec；输出 = **决策项 + 可执行级技术方案**；**零具体产品名**（机制类别可作设计表达）；**不读底座、自包含**（落地侧复用底座机制、冲突以底座等效为准）。
- **对下游 = 黑盒单能力**：authoring **agent 运行体**（非文本玩法）；**8 个宏观抽象节点**（判型与功能地图 / 事实澄清 / 功能规格 / 页面设计（含真设计图）/ 工程设计（含敏感点）/ 内部自评审 / 内部校验（确定性）/ 决议与交付）——每个在具体设计中**可展开为多个子节点、可能有环**；**具体编排待 DESIGN**。
- **运行体机制**：交互中断 = **B 基座**（纯 MCP 续跑契约，确定性落闸：`status`/`questions`/`resume_token`/`answers`，防代答）+ A 增强（MCP elicitation）；**LLM 适配层**（`url + sk` / `sampling` 开关 / 降级链 / 皆无 fail-fast；能力基线只作使用限制、由人决定壳与模型）；**状态** = 产物 + `specs/.authoring.json`（运行元数据**不交付**）。
- **MCP 面**：resource（玩法 / 模板）+ **运行体工具**（黑盒「一句话→spec」）；**校验为内部确定性步骤、不对外暴露**。
- **资产**：问题库 / 模板 / **关系图谱**（使用性质→域→模块）/ **语义替换表**（日常语→专业语）/ RAG（**仅自有资产、不接底座文档**）。
- **设计评审两层**：内部自评审 + 独立评审 agent（消费任意设计规格；演进：并行多 LLM 评审）。
